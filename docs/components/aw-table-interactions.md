# AWTable 开发交互细则

本文件补充 [AWTable 主契约](aw-table.md)，用于组件拆分、事件实现和用例编写。规范已纳入 Design System；应用安装任务与 OTA 包列表按已批准范围接入消费者，其他目标能力逐项实施和验收。静态预览只验证已演示的能力，不能替代本文所有场景的实现验收。

实现取材及明确不复制的旧行为见 [消费者复用审查](../decisions/audits/2026-10-21-awtable-consumer-reuse.md)。字段、权限、状态转换、日期传输与批量接口仍由领域适配器提供。

## 1. 组件边界与唯一所有者

| 单元 | 输入 | 输出/副作用 | 所有者 |
| --- | --- | --- | --- |
| AWTable | rows、total、columns、query、status、actions、selection | 查询/选择事件、行操作意图；不直接请求 | 视图 |
| AWTableFilters | schema、完整 draft、applied、expanded、提交状态 | 修改草稿、搜索、重置、展开；不改机构或偷偷查询 | 筛选视图 |
| AWTableRegion | filters、toolbar、batchBar、children、pagination | 区域布局；无业务数据副本 | 组合壳 |
| useAWTableState | 初始查询、上下文、恢复策略 | query、search、reset、onQueryChange、内部重取意图 | 查询控制器，可被现有状态层替代 |
| useAWTableRequest | 查询意图、上下文就绪状态、load 适配器 | rows、total、status、error、retry | 唯一读请求所有者，可被现有请求框架替代 |
| ColumnPlanner / AWTableActions | 语义列、完整动作组合、容器、字体、语言 | 整表宽度、固定策略、行内/更多分配 | 内部规划与动作执行 |
| 配套能力 | 已有 StatusIndicator、TMSEmpty、机构树、弹窗、导出、恢复工具 | 通过受控 props、slot、事件组合 | 独立复用，不塞进表格内核 |

简单详情表只装配 AWTable；远程列表增加筛选和请求适配器；带机构树的列表由页面把机构布局与 AWTableRegion 组合。不要增加 `isOta/isResourcePackage/withOrgTree` 等业务布尔开关，也不要要求已有请求框架的页面强制使用新 Hook。保持一个 query、一个选择值、一个请求所有者；局部组合可共享 state/actions/meta，但不引入第二套全局 store。

### 同步受理与异步执行

可选 Hook 组合使用 `table.requestCoordinator` 作为同一实例的稳定协调句柄，并传给 `useAWTableRequest({ coordinator, query, refreshVersion, contextKey, gate, load })`。协调器持有同步 gate、当前 requestId、受理锁和合并重取标记；它不持有第二份 query/rows。请求 Hook 是唯一读取所有者，绑定与销毁均按实例代际清理。

1. AWTableFilters 先同步占用验证锁，再捕获 draft/version/context 进行验证；验证失败或草稿/上下文已变时结束，不发查询意图。异步验证 pending 也显示 submitting，防止相同草稿同时验证后各自提交。
2. 通过验证后，search/reset/page/sort/retry 统一调用协调器的 `tryAccept(intent)`。gate 未就绪或同实例前台 pending 时返回拒绝，不改 query。受理立即分配 intentId 并同步上锁，再原子更新 query 或重取版本；禁止等 React render 后才锁。
3. 请求所有者只消费该 intentId 一次，并给它分配 requestId。`query` 与 `refreshVersion` 用于描述该次快照，而不是再额外触发第二条 effect 读取；首次 ready/恢复/上下文 ready 也走同一调度入口。重置到相同 query 等无需读取的事件同步完成并释放受理锁，不能一直等待不存在的请求。
4. 完成时协调器的 `settle(requestId)` 只释放匹配当前实例与代际的锁；旧 finally 无权释放。取消、卸载与依赖阻断使旧读失效。控件 disabled/loading 从协调状态派生，只是显示反馈，不是唯一执行防线。
5. 同步拒绝的重复点击不排队；唯一允许的队列是一次“写操作已成功、当前结果需要更新”的合并标记。受理与读取结果应可在测试中分别观察，但不向产品 UI 暴露调试字段。

以上 `tryAccept/settle` 是协调器内部协议，不要求公开给页面调用。已有请求框架的接入直接使用受控 AWTable/Filters，按同一语义实现单所有者协调；不同时挂载可选请求 Hook。无远程查询的 local 模式不需要请求协调器。

## 2. 状态词典

| 名称 | 含义与约束 |
| --- | --- |
| draft | 当前完整编辑值，含已收起字段；可以与 applied 不同 |
| applied / query | 最近一次被接受的有效查询；并不代表请求已成功 |
| resultQueryKey | 当前屏幕结果对应的查询标识；用于判定旧结果，不从 draft 推算 |
| contextKey | 表格实例、用户/租户授权范围和当前业务上下文的稳定标识；由调用方构造，不含凭据 |
| queryKey | contextKey + 归一化 filters + sort + page/pageSize；使用领域规范化后的稳定序列化 |
| requestId | 每次被调度读取的递增代际；success/error/finally 均比对代际及 contextKey |
| selection | key 集合及范围策略；与 rows 对象缓存分离 |
| actionPending | rowKey + actionId + contextKey 的执行锁；必要的同一行互斥由业务声明 |
| restoreSnapshot | 白名单允许的 draft/applied/展开/页码等；不包含 pending、弹窗和行对象 |
| columnSettings draft / hiddenIds | 浮层临时草稿与已应用隐藏列集合；独立于业务 query，关闭取消时不提交 |
| columnSettings scopeKey | 调用方提供稳定用户/租户身份范围；与表格 id、schemaVersion 隔离，不随当前机构选择变化，不含凭据 |

对 filters 的相等比较不能使用对象引用或未经归一化的任意 `JSON.stringify`。白名单字段固定顺序；日期规范化；空值和“全部”哨兵由 schema 声明；多选是否无序由领域声明，不擅自排序有序数组。语言和显示标签不进入业务 queryKey，切语言重新测宽而不重查业务数据（接口本身依赖 locale 时由适配器声明）。

## 3. 事件表：从用户意图到请求

以下是目标远程列表默认规则。一次读取指一次协调器调度；后端鉴权重试属于 API 层，不能拿它解释组件的重复订阅。local 模式执行同样的查询转换，但不发 HTTP。

| 触发 | 查询/草稿变化 | 读取 | 选择、焦点和滚动 |
| --- | --- | --- | --- |
| 输入、清空单字段、选择“全部” | 仅 draft | 0 | 保留选择；焦点留控件 |
| 展开/收起高级筛选 | 仅 expanded | 0 | 隐藏前若焦点在高级区，归还展开按钮；不丢值 |
| 搜索：完整草稿不合法 | 保留 applied/query；标记错误 | 0 | 展开首个错误所在区，聚焦错误字段；保留结果与选择 |
| 搜索：条件相同 | query 不变 | 1 | 当前页、排序、页大小和同查询选择保留；不跳顶 |
| 搜索：条件变化 | 完整替换 filters，page=1 | 1 | 默认 page/query 范围选择失效；结果区回顶部，不抢输入焦点 |
| 前台读取 pending 时重复搜索 | 不变 | 0 | 同步锁阻止双击、Enter、程序性重复 submit |
| 重置：目标与 query 不同 | 默认 draft/applied、page=1；排序/页大小按配置；收起 | 1 | 清错误和选择；保持机构；焦点留重置 |
| 重置：query 已是默认，仅 draft 脏 | 只恢复 draft/展开/错误 | 0 | 明确重置仍清选择；搜索承担主动重取，不用 reset 代替 refresh |
| 页码改变 | 仅 page | 1 | query 范围选择保留，page 范围清理；结果区回顶部 |
| 选择当前页码 | 不变 | 0 | 保持焦点与滚动 |
| pageSize 改变 | pageSize 与 page=1 原子改变 | 1 | 不分别触发 size 与 page 两次请求 |
| 排序升序/降序/取消 | sort 与 page=1 原子改变 | 1 | 按主契约默认清 query 范围选择；宣告排序 |
| 内部错误重试 | 保留失败请求的已应用查询；不提交 draft | 1 | 保留错误直到请求受理；焦点不主动移进表体 |
| 切机构、租户或业务对象 | contextKey 新代际，page=1；其他值按领域策略 | 就绪后 1 | 立即隔离旧数据/选择/动作；不把空范围当全量 |
| 关闭承载 AWTable 的弹窗/抽屉，或表格卸载 | 使被销毁表格实例的读请求失效 | 0 | 不让旧返回覆盖重新打开的新实例；行编辑弹窗关闭只失效其自身表单代际 |
| 写操作成功 | 发起上下文仍有效时，当前最新 applied 查询不变 | 同上下文合并重取 1 | 不提交旧闭包的 query 或新 draft；只清理对应选择；旧上下文完成由外层反馈 |
| 删除后页码超出 total | page 校正到 max(1,ceil(total/pageSize)) | 最多补查 1 | 无新 total 时先重取；本代际禁止无限校正循环 |
| 切表格/卡片 | 查询和数据所有者不变 | 0 | 同一选择范围；纯呈现切换不重查 |
| 打开列设置、勾选列 | 从当前 hiddenIds 初始化草稿；只改草稿 | 0 | 必选列保持勾选；表格和查询不变 |
| 应用列显隐 | 一次提交 hiddenIds，重算可见列宽度 | 0 | 页码、页大小、筛选、排序与选择不变；关闭后安全归还入口焦点 |
| 取消、Escape、外点关闭列设置 | 丢弃草稿 | 0 | 当前显隐与偏好不变；不误触排序 |
| 列设置恢复默认 | 草稿改为全列，等待应用 | 0 | 当前表格不变；可取消这次恢复 |
| 列设置上下文或身份/表格/版本变化 | 关闭浮层、丢弃旧草稿；按当前隔离键恢复偏好 | 0（列设置） | 机构变化仍按领域触发读取，但不改变同身份的列偏好 |
| 切语言/主题/容器大小 | 仅呈现与宽度缓存 | 0 | 不关闭业务弹窗、不重置查询、不抢焦点 |
| 返回列表恢复 | 先校验快照，再一次性初始化 | 1 | 不先默认查询再恢复查询；数据提交后恢复可用焦点/滚动 |

默认前台查询 pending 期间禁用搜索、重置和分页/排序提交入口，草稿可继续编辑，机构/权限上下文切换仍可立即取消旧读。下次搜索使用最新 draft，已发请求使用提交时的不可变快照。完成、失败或被当前上下文取消后解除锁；旧 finally 不得解除新请求的锁。若业务确需快速连续翻页，适配器可采用 latest-wins，须明确取消旧请求并追加乱序测试，不同时启用两套策略。

## 4. 筛选字段和选项

### 布局与组合

- 标准、上下文、紧凑三种示例复用 AWTableFilters；不另立 FilterPanel 契约。字段数量、顺序、基础/高级分组与 span 来自页面 schema，不能强制所有页面两行或每行 3/4 项。上下文中的机构范围由业务适配器负责，不内置为通用字段或自动计数。
- 基础与高级区域共享同一组列轨道，同列控件左右边界跨行对齐；关键词、日期段可占 2 列或整行，跨列端点仍对齐公共边界。以实际容器逐步减列，不为每一行分别算比例；标签位于控件上方，维持 schema 与键盘顺序。
- 面板四边、字段网格横纵及基础/高级区之间均为 16px；紧凑示例不缩小这些间距。局部标签、日期端点与按钮内部间距沿用对应控件规则。
- 精细指针桌面默认 32px 控件高度；粗指针或筛选容器不超过 575px 时，输入、选择、日期端点、展开/重置/搜索与上下文选择的标签点击区高度至少 44px。尺寸变化只影响布局，不能产生提交、重置或展开事件。

### 编辑与验证

- 字段具备稳定 id、可见 label、错误关联；placeholder 仅说明格式，不替代 label。清空按钮只清草稿，不执行查询。多选去重按稳定 value；值为 0/false 不等于空。
- 点击搜索和单行输入 Enter 走同一 Form submit；IME composing 和多行输入不能误提交。提交时捕获完整 draft；只接受当前 draft 版本和 contextKey 对应的异步验证结果。
- 高级区收起后保值、计数、验证、提交完全一致。错误落在隐藏字段时先展开，再滚到字段并聚焦；若用户已经移动焦点或切上下文，旧验证不再抢焦点。
- 提交失败后对应错误持续显示；字段重新编辑时只重新校验受影响字段/依赖。重置清验证状态；服务端字段错误通过适配器映射，未知错误显示表单级说明。
- 不显示独立“筛选条件”标题行，但 section 保留本地化可访问名称。底栏左侧为已启用计数，右侧依次为更多筛选、重置、搜索；计数为 0 也显示，窄容器下操作组可另起一行并保持右对齐，计数保持左对齐；重置与搜索保持相邻的一组，不挤压按钮。DOM 和键盘顺序与视觉顺序一致；无高级字段时省略展开入口。已启用数统计 applied 字段；修改多个值仍按字段计数。仅有高级条件时，收起入口显示高级已应用数量，不能让隐藏条件悄悄生效。

### 远程选项与联动

- 机型/机构候选等由外层提供 options、loading、optionsError、onRetryOptions。选项加载不是表格首次加载；失败仅在该字段展示重试，保留当前值和其可读标签。
- 远程关键词候选请求具备自己的请求序号、取消和上下文隔离；不能复用表格 requestId，亦不能阻塞独立结果区。
- 暂未加载到已选值不能擅自清空。适配器确认选项失效/无权访问时，显示原因，清理或阻止提交的规则由字段声明；禁止把失效值默认为“全部”后自动扩大范围。
- 父字段改变使子字段失效时，一次 onDraftChange 原子更新父子值；提示子字段需重选。尚未搜索前不改 applied，也不发两次结果查询。
- 无权限字段从 schema 移除后，调用方原子清理其 draft/applied 与请求参数；若清理会扩大查询范围，先按领域授权规则决定是否可查询，不能由通用组件推断。
- 日期段完整性、时区、日首日尾、开放区间按主契约处理；显示格式与传输格式分离。复制技术 ID、版本号时保持原始值，不按数字或时间格式猜测转换。

## 5. 请求准入、结果和错误

### 请求开始前

可选请求层接受明确的准入状态，由领域适配器计算：

```ts
type AWRequestGate =
  | { state: 'ready' }
  | { state: 'waiting'; message: string }
  | { state: 'blocked'; reason: 'scope-error' | 'no-scope' | 'forbidden'; message: string };
```

`waiting` 表示依赖未准备好，`blocked` 表示当前不能读取，二者均不调用 load。请求 Hook 返回 gate，以及同名的 status 和 gate.message 对应的 statusMessage；AWTable 显示依赖状态，AWTableFilters 的 disabled 绑定 gate 非 ready，区域 slot 可提供依赖重试。主契约 React 用例示范这一接线。不使用空数组、null 机构或零 total 暗示“不限机构”。gate 由 waiting 转 ready 且上下文稳定后读取一次；权限改变立即失效旧结果与选择。恢复权限/机构依赖的重试由该依赖负责，不能直接调用表格 retry 绕过 gate。普通独立表格可显式使用 ready。

### 请求结束后

| 情况 | 数据和状态 | 可执行行为 |
| --- | --- | --- |
| 首次等待/读取 | 保持列结构，未知 total 不冒充 0 | 可编辑草稿；依赖未就绪不可搜索 |
| 当前查询成功 | 原子提交 rows/total/resultQueryKey，再解除 pending | 正常操作；单个成功结果只播报一次数量 |
| 当前查询失败且无同查询旧结果 | 区域错误；不显示空态、不清 draft | 重试当前 applied；更改筛选后搜索 |
| 同查询更新失败且有旧结果 | 保留旧 rows/total，持续注明“更新失败，显示上次结果” | 明确重试；只读查看可用；状态相关写动作须重验 |
| 已有结果的分页 / 搜索 / 刷新 pending | 结果区域不增加可见文字条；保持表内 loading、aria-busy 及不占布局的加载播报，表格位置与高度不因提示行改变 | 默认禁止旧结果的行写入和选择；不得把旧 total 当新 total |
| contextKey 改变 | 立即移除旧上下文结果和动作 | 等待新的 gate，不允许过期数据继续操作 |
| 旧成功/错误/finally | 全部忽略 | 不覆盖当前数据/错误，不提前结束新 pending |
| AbortError | 同代际取消后转交后继/idle，不提示“失败” | 取消读不代表服务器取消写 |

错误分区：机构、筛选选项、统计摘要、表格行、批量结果各自拥有状态与 retry。摘要失败不能让表格变为空，表格失败不能抹掉可用的机构列表。关联读取可用 allSettled 收集；是否允许部分展示由领域适配器声明。错误文字本地化，诊断细节不将凭据或整个响应直接展示。

写操作完成的重取是通用协调规则：先比对发起时的 contextKey；已切身份/机构时不刷新新列表、不改变新选择、不归还旧焦点，仅由外层报告该操作结果。同上下文下读取最新 applied 查询；若已有前台读取，合并为一个待更新标记，当前读取结束后最多补查一次，补查使用届时最新 query。标记只属于原上下文，切上下文即丢弃；不能同时调用 reload、更新 query 和递增版本产生多次读取。

## 6. 行动作与确认闭环

1. 按领域权限和状态生成可见/禁用动作，再进行数量及宽度规划。隐藏项不计数；禁用项保留位置并提供可访问原因。权限消失时关闭受影响菜单和确认，不能继续使用旧动作闭包。
2. 每行最多 3 个可见入口（含“更多”）：无菜单时普通 1–3 项直露；4 项起或存在危险菜单项时最多 2 项＋更多，实测宽度不足可继续收纳。登记的危险直接展示例外也占用入口名额。普通动作顺序稳定，危险项末尾分组。业务按钮及菜单不加图标，保留展开等交互标识。
3. 打开更多时保存触发器。Enter/Space 打开，方向键/Home/End 移动，Escape 关闭并归还焦点，Tab 正常离开；点击外部关闭不把焦点拉回。滚动或 resize 后无法维持正确锚点时关闭，禁止脱离行悬浮。
4. 触发动作前同步设置行 key+动作 id 锁，再进入确认或异步回调；不能只依赖下一次 React render 的 loading。有确认时先锁为 confirming，取消释放，确认时原子转为 executing；重复点击不能打开多份确认。只禁用相关互斥动作，不全表变灰。详情/复制等独立动作是否可并行由适配器声明。
5. 破坏性操作只出现一次确认：标题说明动作，正文含对象名称/数量和后果，按钮写明确动词，默认焦点在取消。行内/更多位置不改变确认规则；调用方不得再包第二层 Popconfirm。
6. 确认提交后保持确认按钮 loading，阻止重复提交；是否允许关闭由任务语义声明。失败保留确认和错误以便重试，不先关闭再只发短暂 toast。动作适配器与共享层声明唯一反馈所有者，避免同一错误由接口拦截器、组件和页面重复提示。写操作没有通用自动重试；失联结果不确定时先核对服务端状态，不能直接重复提交。
7. 仅由领域适配器声明数据失效的写操作成功才合并重取；查看、复制、下载完成不自动刷新，不能根据动作名称猜测。适配器是失效意图的唯一发出者，共享执行器不再追加另一条读取。失效时先核对发起 contextKey，仍在同上下文才刷新最新 applied 查询；旧上下文结果由外层处理，不污染新列表。保存成功但列表重取失败时，分别显示“保存成功”和列表更新失败，不能伪装保存失败而诱发重复写入。
8. 关闭确认/表单后，原按钮仍连接、可见且可用才归还焦点；对象被删除时依次使用同位次下一行动作、前一行、表格区域/标题。用户已经移动焦点则不抢回。使用 preventScroll 避免列表跳动。

## 7. 选择、批量操作与导出

### 选择

- 表头全选仅作用于当前页可选择行；全不可选时禁用。半选态只按当前页可选行计算，显示的已选总数按声明的选择范围计算。
- 点击行链接、菜单、复选框分别执行自己的动作，不能冒泡触发整行跳转/切换选择。稳定字符串 rowKey 跨页保持；不能使用行下标或把 Snowflake 转数字。
- 翻页、排序、过滤、恢复、机构切换分别按主契约保留策略处理；选择变化必须带原因，清理后可简短提示，不静默保留跨上下文 key。
- 同查询重取保留 key，但重新检查可选性/权限；当前页没有出现的跨页 key 不能据此删除。提交批量前以服务端校验为准，不以缓存行状态授权。

### 批量结果

调用方提供能力允许的批量动作；组件不默认生成批量删除、推送或全部匹配全选。打开确认时就冻结 contextKey、动作、keys 或后端快照和数量（无需确认的动作在触发时冻结）；确认和执行期间选择变化不能静默扩大操作集合。确认前复核资格，范围失效时提示重新选择，不偷偷按最新选择执行。

```ts
type AWBatchOutcome = {
  succeededKeys: readonly string[];
  failed: readonly { key: string; message: string; retryable: boolean }[];
  unknownKeys: readonly string[]; // 请求失联等，结果未确认，不等同失败
};
```

这是组件结果呈现的目标结构，领域接口由适配器转换，不要求后端改用此格式。长任务的“已接受”不能当执行成功，需由业务任务页跟踪最终结果。

- 全成功：移除本次成功的选择，关闭批量条或保留后来新选的项目，合并一次重取。
- 部分成功：移除成功项，保留失败/未知项，展示成功/失败/待核对数量和明细。只对 retryable 失败提供重试；未知结果先核对，不自动重发。
- 总体失败：保留选择和错误；不声称每一项均失败，除非后端逐项确认。当前上下文已变化时，结果交给页面反馈，不把旧 key 加回新列表。
- 失败明细导出仅在领域提供数据和权限时出现，不把真实错误行自动写进本地持久化。

### 导出配套能力

吸收现有 useExport 的上下文反馈、非空文件校验和文件名兜底，保留为独立工具。封装时补充同步防重、上下文隔离、错误响应识别和明确的导出范围：当前页、明确已选项或所有匹配结果由业务声明。导出捕获 applied 查询/选择快照，不能用未提交 draft；分页参数是否携带由范围决定。没有服务端全量导出能力时，不以当前页冒充全部。空 Blob 或错误 JSON 不触发下载；下载成功后释放对象 URL。

## 8. 列宽、文本与布局算法

主契约规定语义宽度和动作宽度。本节补足实现触发和稳定性：

| 环节 | 实现要求 |
| --- | --- |
| 可用宽度 | ResizeObserver 的 contentRect/contentBoxSize 直接使用；若用 getBoundingClientRect 的 border-box 才扣边框和 padding，clientWidth 则仅扣 padding；仅额外扣尚未扣除且占用内容区的纵向滚动条，禁止重复扣减。不按 window.width 或机构树固定猜值 |
| 测量字体 | 使用实际 font-family/size/weight、当前语言的动作/表头；fonts ready/loadingdone 后重算；未就绪先保守布局，不闪成零宽 |
| 普通数据列 | min 保证表头和最小可读内容；preferred 为常用预算；max 仅约束数据列弹性。至少一个可伸缩内容列承接剩余空间 |
| 动作列 | 由声明的所有有效组合计算整表稳定宽度；不按当前页最长一行反复变宽；无动作整列可省略（配置明确，不逐页消失） |
| 空间不足 | 先收纳低优先级动作；主操作+更多仍放不下则扩动作列，随后按顺序解除固定并横滚，不能截断按钮 |
| 选择/展开 | 宽度纳入列总宽和固定预算；长表头/自定义选择控件需实际测量，不能沿用示例 40px 而裁切 |
| 固定预算 | 先留关键非固定数据列的最小阅读区，再冻结边列；次要左列→右操作→主标识依次退让 |
| 观察器稳定性 | 只在有效尺寸或测量键变化时更新；同一帧合并读写，忽略无变化结果，卸载断开 observer；避免自身改宽形成振荡 |
| 语言/密度切换 | 清对应测量缓存，保留查询和选择；异步测量不能倒退到旧语言布局 |
| 横向滚动 | scroll.x 为列规划总宽（虚拟化为数值）；仅表体区域横滚。冻结阴影只在有遮挡内容时出现 |

普通数值、时间和动作左对齐，金额右对齐，数字 tabular-nums。日期格式化走统一 locale/时区；无值使用统一占位，0/false 是真实值。状态必须有文字且未知状态有中性兜底；通用组件不推断“已上架/成功”等领域含义。

| 列 semantic | 默认呈现 | 适配边界 |
| --- | --- | --- |
| text | 左对齐、末尾省略、实际溢出才提供全文 | 备注是否多行由列声明；HTML 按文本转义 |
| identity | 左对齐，名称链接由调用方提供；技术 ID 可等宽/中间省略 | ID 保持字符串，复制原值；全文与详情入口不能争抢同一触摸 |
| status | 文字＋语义色/辅助形状，文字不省略 | 状态 code→语义由领域映射；未知 code 中性展示，不猜成功 |
| number / size | 左对齐、tabular-nums、本地化数值/容量 | 明确单位、精度和舍入；0 保留，不能写成占位 |
| amount | 右对齐、tabular-nums | 币种、精度、千分位按领域；不能只按字段名含 price 自动猜币种 |
| dateTime | 左对齐，统一 locale 与 IANA 时区 | 无 offset 的业务日期不擅自当 UTC instant；完整时间可访问 |
| custom | render 使用同一留白、焦点、主题约束 | 交互控件有名称；不在每行重新嵌入查询或共享工具栏 |

`null/undefined` 按统一缺省标记处理；空字符串是否缺省由该字段声明；无权限不等于缺省，未知枚举也不等于空值。formatter 的显示结果不能反向作为排序参数、权限码或 API 标识。

长文本只在实际溢出时提供全文入口。借鉴 OrgTreeTitle 的测宽与 hover/focus/click/Escape 支持；完整文本供读屏和复制，不把每个短单元格都变为 Tab 停靠点。中间省略适合 ID/路径，名称默认末尾省略，由列 semantic 声明。带详情链接的单元格保留链接行为，全文查看另有明确入口，不能同一次触摸既开详情又开 tooltip。

## 9. 滚动、键盘和动效

- 分页/变条件/排序完成后只重置结果区纵向滚动；页面外壳、机构树、筛选区不跳动。同查询更新保留行锚点/横滚位置；数据减少时裁到合法位置。
- 焦点留在触发的按钮/输入；若被禁用导致浏览器丢焦，完成后仅在焦点仍在 body 或原触发器时恢复。不能每次 render 主动 focus 表格。
- 横滚区域仅在实际需要滚动时进入 Tab 序列，提供可访问名称；禁止给每个 td 加 tabIndex 或随意使用 grid role。隐藏测量行不能进入 Tab 序列。
- 菜单、全文层和确认层必须有稳定挂载位置，不能被 overflow 裁切。打开后基于实际锚点定位，首帧不可先在错误位置显示再跳转；关闭后清监听器和临时层。
- 筛选展开不重挂整个结果区；批量条出现不盖住聚焦元素。筛选控件的桌面 32px 与粗指针/窄容器至少 44px 点击高度按第 4 节执行；触屏/缩放导致内容多行时，行高可超过密度基准。
- “显示列”是结果工具栏右侧与视图切换同组的 32×32px 浅底 ControlOutlined 图标按钮；悬停/聚焦提示本地化“显示列”，aria-label 同名，展开高亮并隐藏提示，不在表头重复显示。没有视图切换时仍放在工具栏右侧，机构/总数摘要在左侧；卡片视图隐藏显示列。入口在表格横向滚动区域外，不因固定列或列显隐移动；窄屏自然换行仍可达，焦点顺序随 DOM，关闭后按已有规则返回有效入口。
- 列设置浮层具有本地化名称，复选框列表显示全部列名；必选项保持勾选并禁用，不增加附注文案。内容过长可滚动，底部保留恢复默认、取消、应用。Escape 关闭，正常关闭安全归还焦点，contextKey 变化时不能把焦点拉回已失效上下文。分页总数居左、控件居右，表格/卡片共用呈现；窄容器换行而不裁切。
- reduced-motion 下跳过非必要过渡；加载时保持表头、分页区和布局，不以快速骨架闪烁代替短请求。已有结果的分页、搜索和刷新不得在表格上方新增“正在更新/暂时显示上次结果”等可见文字行；使用表内 loading、aria-busy 及屏幕阅读器加载状态。首次加载、waiting/blocked/forbidden、首次错误仍保留各自状态；更新失败继续显示持久旧结果警告与重试。延迟指示可以配置，但真实 pending 防重从受理瞬间开始。

## 10. 详情返回、恢复和存储

1. 导航前保存允许的 applied query、独立 draft、expanded、视图和必要滚动锚点；快照 key 含应用/用户/租户/表格/schema 版本。敏感搜索值可显式禁用持久化或仅使用内存。
2. 返回时验证 JSON 类型、schema 版本、页码正整数、pageSize 白名单、列/排序能力、过滤值和 contextKey；只恢复允许字段，不把未知 key 浅合并进 query。
3. 存储不可用/损坏时回退默认值；失效排序/字段只清理对应部分，权限/上下文不匹配则整个快照失效。不要因日期反序或已删除机构自动扩大查询范围。
4. 先完成恢复再发首次读取，避免默认页与恢复页各请求一次；total 说明页码越界时最多校正一次。数据渲染后恢复可用行锚点，找不到则靠近原位置，不访问不存在 DOM。
5. 不恢复选择令牌、执行中状态、打开的确认/弹窗、整行数据、凭据或错误响应。登出/换身份清理不适用快照。浏览器后退与页面返回入口使用同一恢复规则。
6. 列显隐偏好与查询快照分离，只有 `{ schemaVersion, hiddenIds }`，键包含应用、scopeKey、表格 id 与版本。scopeKey 包含用户/租户身份，不使用机构树当前选中值；contextKey 变化仍立即关闭弹层和临时草稿。默认全列；identity 默认必选，首个 identity 或无 identity 时首列与操作列始终保留。恢复时剔除未知、重复、必选隐藏 id，新列可见；非法 JSON、错误版本或非纯字符串数组回退默认，不读取旧 OTA 列缓存。写存储失败保留当次已应用显示，不阻断列表。

## 11. 独立配套：机构、表单和自动更新

这些是可吸收的共同模式，但不作为 AWTable 内置业务能力或强制公开新组件名。

### 机构树

沿用 OrgTreeSider 的搜索、长名称和窄屏抽屉；数据域保持单独 hook。用户/租户/角色/权限改变时，授权机构与默认选中同时更新，先阻断旧数据再显示新范围。树无数据、无权限、加载失败不同于“全部机构”；搜索树节点不直接改表格查询，选中节点才提交一次上下文事件。

### 表单弹窗/抽屉

沿用现有滚动壳和焦点恢复；表单字段仍由业务提供。一次打开有独立 instanceKey，默认值只对该次初始化，详情晚到只补 untouched 字段；入场动画结束的 afterOpenChange 不能覆盖已经输入的内容。切编辑对象创建新代际，旧详情响应不能写进新表单。校验失败定位字段；保存失败保留输入；关闭脏表单按产品已批准规则拦截；成功后关闭并刷新最新列表查询。反馈使用 App.useApp 上下文，不新增静态 message/modal。

### 实时任务的自动更新（可选适配器）

普通列表默认不开启轮询，不恢复独立刷新按钮。已有实时任务场景可吸收可见性暂停、失败退避和单计时器：

- 页面隐藏/离线/卸载/权限不就绪时停止调度，恢复后在适配器声明的数据过期条件满足时读取一次。
- 前台搜索/分页优先于后台更新。后台读取中收到有效用户意图时使后台读失效并发起前台读，不能吞掉用户搜索；前台 pending 时不叠加轮询。
- 业务成功重取沿用第 5 节的通用合并规则；自动更新适配器不另外发起一次重取。
- 后台结果不改 query/draft/page/selection，也不抢焦点或重置滚动；状态变化导致动作不可用时及时重算。
- 间隔、退避上限、任务完成停止条件由领域配置；取消后旧计时器不能复活。详情摘要和设备分页可分别更新，摘要变化不能强迫设备列表回首页。
