## 生效规则

- 独立详情统一使用内容区 PageHeader：同一个 `header` 的标题行内先放左箭头与可见“返回”文字，再放标题与状态。返回按钮与标题并列，不嵌入 `h1`，不混入右侧业务操作。英文为“Back”。
- 应用顶栏只挂载面包屑；详情返回与标题留在内容区。面包屑表示位置，返回用于离开当前详情，两者可以同时存在。
- 返回不依赖详情数据加载成功或查看权限：加载、空数据、错误及 403 均保留该入口。403 状态不展示受限对象数据，仍使用安全的业务父页兜底。
- 移动端和 sticky 紧凑态保留返回及完整按钮文字。标题可在自己的区域换行，操作区可换行，返回与标题保持同一行。
- 显式业务目标优先，其次使用已验证的站内来源；直接打开、刷新后来源不可用或来源无效时回到业务父页。保留来源机构、列表筛选、分页及已有滚动恢复，不无条件调用 `history.back()`。
- 审核、消息等来源继续按各自已确认流程返回。表单和向导保留未保存变更拦截，不重复展示面包屑；向导的退出返回与步骤“上一步”职责不同。
- 统一仅覆盖页头导航与呈现。设备、应用、OTA 包、资源包和任务等详情保留各自正文、Tabs、统计与操作结构；抽屉/弹窗详情继续使用关闭和焦点恢复，不强加整页返回。
- 顶级列表和仪表盘不增加返回。文档站工具栏的章节历史与业务返回保持区分。

## 文档站示例一致性

本节按已有导航语义修正文档站示例，不增加消费者业务能力或改变机器契约。

- 来源感知的退出按钮统一写“返回 / Back”，不能写成承诺固定层级的“返回上一级”。“返回列表 / Back to List”“返回首页 / Back to Home”必须配置明确目标；步骤“上一步 / Previous”保持步骤导航职责。
- PageHeader 的导航说明与面包屑位置说明分开。详情返回位于内容区标题前；表单、向导可以使用独立返回行，结果页可以使用固定目标动作，不机械套用详情布局。
- 共享返回按钮保持 32px 高度、完整文字及键盘焦点。非中文按钮的通用自适应样式不得覆盖返回按钮高度，窄屏筛选栏不得拉伸返回按钮。
- 文档刷新或进入无法验证的历史条目时重新建立站内导航范围；此时返回使用明确目标或安全兜底。不能把旧会话的历史条目当成新站内访问，再调用浏览器后退。
- 一致性校验遍历全部章节，根据导航属性、箭头、文案和公共样式识别返回控件。可选浏览器回归覆盖中英文、明暗主题、1440px / 1024px / 390px、直接进入与键盘激活、刷新后原生后退及前进。

复验命令（从独立 QA 环境提供 `PLAYWRIGHT_MODULE` 和 `AXE_SCRIPT`，不为静态站添加运行时依赖）：

```sh
node scripts/router-runtime.test.js
node scripts/check-consistency.js
node scripts/back-navigation-browser.test.js --output /tmp/angelwatch-back-navigation
```
